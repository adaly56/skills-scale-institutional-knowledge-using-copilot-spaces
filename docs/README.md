# OctoAcme Project Management Documentation

This documentation suite describes how OctoAcme coordinates cross-functional projects from an initial idea through planning, delivery, release, and retrospective. Projects begin with a clear problem, measurable outcomes, stakeholder alignment, and a decision to proceed. Teams then shape the approved work into a prioritized backlog with acceptance criteria, milestones, owners, and known risks. During execution, teams make progress visible on a project board, communicate regularly, and use reviews and testing to maintain quality. Releases include readiness checks and post-deployment verification, and retrospectives turn lessons into owned improvement actions.

## Quick start by role

- **Project Managers (PMs):** Start with the [Overview](octoacme-project-management-overview.md), then use the [Initiation Guide](octoacme-project-initiation.md) and [Project Planning](octoacme-project-planning.md) to establish the project. Keep the [risk register and communication plan](octoacme-risks-and-communication.md) current, and use [Execution & Tracking](octoacme-execution-and-tracking.md) to manage delivery.
- **Developers:** Review [Roles and Personas](octoacme-roles-and-personas.md) and [Execution & Tracking](octoacme-execution-and-tracking.md) for board states, pull request expectations, and testing practices. Refer to [Project Planning](octoacme-project-planning.md) for acceptance criteria, estimates, and dependencies.
- **Product Managers (PdMs):** Begin with the [Overview](octoacme-project-management-overview.md), then use the [Initiation Guide](octoacme-project-initiation.md) to define the problem and success measures and [Project Planning](octoacme-project-planning.md) to prioritize the backlog. Use [Risk Management & Communication](octoacme-risks-and-communication.md) to stay aligned with stakeholders.

## Key principles

- **Customer-first:** Prioritize customer value and usability.
- **Iterative delivery:** Deliver small, testable increments and improve them based on evidence.
- **Clear ownership:** Name a Project Manager and Product Lead for each project, with responsibilities understood across the team.
- **Data-informed decisions:** Define success measures and use them to evaluate impact and guide decisions.
- **Psychological safety:** Encourage feedback, candid retrospectives, and learning.
- **Quality and transparency:** Make work, risks, and blockers visible; build testing and release verification into delivery.
